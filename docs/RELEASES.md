## 2026-10-16 · v0.4.11 运行期网络与状态保存移出游戏主线程（已部署）

- 插件主线程只采集独立数据快照、接收已完成任务和执行原版游戏操作；HTTP 请求打包、响应解析、任务筛选和皮肤版本计算均在后台完成，后台不读取角色、场景或在线玩家对象。
- 新增单独的状态写入线程：后台读取恢复文件，序列化并刷盘后原子替换状态文件。保留一个正在写入的快照和一个累计待写快照，连续保存合并但保留未确认事件；失败保留原快照重试，不让后写的状态被旧写入覆盖。
- 增加保存完成检查：比赛领取保存后才切图；第一轮结束立即延长原版回合计时，结果与下一轮占用信息保存后才执行换边和清理；上传确认的本地记录保存后才允许继续流程。取消比赛先保存审计备份，再保存释放状态，之后才通过心跳确认取消。
- 请求、写盘、恢复文件错误不在游戏线程等待。恢复文件损坏时停止领取任务且不覆盖旧记录；正常卸载尝试限时刷出。强杀进程仍可能损失未落盘的最后快照，此时按原有规则转核查，不推测比分；已保存的事件按相同编号重试。启动时一次性读取插件配置、地图初始化时应用原版外观规则仍保留原位置，不属于逐帧运行期工作。
- 本地验证包括慢盘、慢 HTTP、写入失败恢复、数据快照隔离、累计快照合并、取消备份顺序、丢失回复后的重试，以及 C# → 本地网站 → SQLite 的两轮结算和重复回传检查。实际游戏多人切图与半场换边仍需上线验收；不能据此宣称原版单核瓶颈已解决。

## 2026-10-16 · v0.4.10 网页与插件减负（已部署）

- 网页首次加载完整状态，日常轮询只更新本人、队列、当前房间和最近一场比赛；历史、资料和排行榜页面仍读取完整数据。排队和参赛期间维持 2.5 秒轮询，普通浏览 10 秒，后台闲置页面 30 秒；页面重新可见时立即刷新。账号、权限或会话变化时重新获取完整数据，避免混用旧状态。
- 静态文件在网页进程内缓存，CSS/JS/字体引用附带内容版本；依赖变更会连带更新入口版本。文本资源支持 gzip 和按压缩形式区分的 ETag。登录、战绩等个性化 API 继续禁止共享缓存，较大 JSON 使用异步低等级压缩。
- 军械库每 5 秒核对在线玩家的配置版本，只返回改变的配装，恢复默认也会同步；兼容旧网页/旧插件的完整响应。插件把在线身份和配装扫描从每帧降为每 0.5 秒，并缓存兵种、外观查找索引。未变化配置保持对象引用，不重复序列化或重建原版配装；网络失败保留上次成功结果。
- 诊断日志通过后台线程每约 250 毫秒批量写入，连续重复消息合并；队列上限 1024 条，单条上限 4096 字符，写满或写入失败会汇总说明。正常模块卸载尝试在 2 秒内刷出；强杀进程可能损失最后一批诊断日志。比赛事件与赛果的持久化队列未改动。
- 验证覆盖压缩与缓存失效、会话隔离、配装版本/重置/兼容、日志拥塞和已有比赛回归。需要先更新并重启网站，再更新并重启游戏服；实际延迟、带宽和单核改善仍需同地图、相近人数的线上对照，不能保证消除原版模拟或线路导致的卡顿。
